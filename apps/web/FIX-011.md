# FIX-011 verification and handoff

Implemented bounded GET/keyed-write retries (500, 1000, 2000, 4000 ms; ten-second total request budget), friendly restart errors for unkeyed writes, and a reconnecting status pill visible both in the village and native modal dialogs. Keys use the existing JSON/FormData `idempotency_key` contract. Unkeyed mutations are never replayed. Exhausted foreground requests return the friendly error; background polls continue with capped backoff. Existing startup fixture fallback is preserved.

Presence stream retries and heartbeat scheduling back off to 60 seconds, suppress errors, and avoid overlapping heartbeats. Village/feed/week/message polling schedules after completion and backs off silently. Vite dev and preview share a proxy handler that returns 503 plus `Retry-After: 2` on refused/reset connections.

`ops/run_api.sh` accepts PORT and preserves externally supplied VILLAGE_ENV_FILE/ASSET_DIR. Its comments document starting an alternate port, checking `/api/health`, changing the Vite target, then stopping the old API. Vite itself still needs restarting when its target changes; this is not a zero-downtime proxy switch. No real server or paid provider was stopped/called during verification.

## Reproduce (PowerShell, from apps/web)

```powershell
bun install --frozen-lockfile
bun run test
bun run typecheck
$env:VITE_MOCK='0'
$env:VITE_DEMO_AUTH='1'
$env:VITE_DEMO_USER='00000000-0000-4000-8000-000000000001'
$env:VITE_VILLAGE_ID=''
bun run build
bunx playwright test --config playwright.fix011.config.ts
bunx playwright test --config=playwright.fix011-regression.config.ts -g 'lost response|unavailable health|authorization errors'
```

The preview test owns only its fixture API on 18011 and Vite on 5181. It tests real socket reset/refusal, stops the fixture API, opens Shop, checks the pill, starts the fixture API, and verifies balance without navigation/reload. The regression config uses 5182 to avoid occupied shared-checkout ports. No secrets are needed for these fixture tests.
