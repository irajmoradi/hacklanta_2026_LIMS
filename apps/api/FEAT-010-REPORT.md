# FEAT-010 — talking-avatar Villager-grams

Branch: `feat/FEAT-010`. API/agent milestone: `e55f52d`.
The subsequent web/docs commit contains this report; use `git log -2 --oneline` for both hashes.

## Delivered

- One optional post-response video render per successful send. Requires generated audio,
  a LAM portrait, and a successful GPU health check bounded to two seconds.
- Migration `018_gram_video.sql` stores video keys and deadlines on gram/outbox rows.
  The database clock controls eligibility and status. Delivery is held until render
  completion or 120 seconds, including if a background task is lost to an API restart.
- Worker failure falls back to audio + portrait. Late results cannot add video to a
  delivery already released by its deadline. Consent and membership checks remain intact.
- Authenticated status polling and a playable preview, with blob URL cleanup.
- iMessage order: disclosure text, video, audio. Successful video suppresses the portrait.
  Per-part in-process progress prevents duplicate video/text/audio on delivery or ack retries.

## Try it

1. Set `VILLAGE_ENV_FILE` to the supplied root environment file; never copy its values.
2. From apps/api, run `& $py -m scripts.migrate`, then start the API normally.
3. For a deterministic offline demo, run the Playwright command above. It starts its own
   Vite server on port 5184, mocks the API/GPU results, and renders the synthetic clip.
4. For integration, run the GPU worker branch providing `/avatar/talk_video?wait=true`.
   Point `GPU_WORKER_URL` to its base URL (a trailing `/health` also works) and use the
   shared asset volume. Start web and the agent normally; retain Photon dry-run unless
   intentionally testing real delivery. Opt in speaker and recipient, configure the
   recipient's phone, select a speaker with a consented voice and LAM head, buy a gram,
   preview, then confirm Send. Rendering appears immediately after audio is generated;
   the player appears when video finishes. With GPU offline, voice + portrait still queue.

## Assumptions, limits, and integration

- No implementation blockers. Real GPU/Photon integration was not exercised; the worker
  branch is external to this task and its specified contract is mocked in tests.
- Worker produces compatible H.264/AAC MP4, so the agent avoids unnecessary transcoding.
  API/worker share the asset volume; Windows drive paths map to WSL `/mnt/<drive>/...`.
- A failed or lost render is not retried automatically; the 120-second deadline releases
  the gram. Existing in-process transport progress does not survive agent restarts;
  delivery retains its existing at-least-once limitation.
- API contract changes are documented in the allowed `packages/contracts/api.md`.
  No additional contract change is required. Integrator may later fold the additive
  migration into `schema.sql`; that file was not edited.
