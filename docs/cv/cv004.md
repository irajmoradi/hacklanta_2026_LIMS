# CV-004 demo cast bake (2026-10-10)

The five seeded villagers have **placeholder faces from CC0 Unsplash photos** (`data/inputs/demo_cast/SOURCES.md`; label them as placeholders in the UI).
They were baked through the real API (`POST /api/avatars/{uid}/photo`, consent=true, X-Demo-User = that user) with `ops/run_gpu.sh` supervising the worker and bridge.

No user fell back to the card.

- Batch run: 5 uploads, then the bridge drains the queue in created order (5 segments, then 5 LAM heads, then 5 bodies). Each heavy model loads once per batch:
  **451 s wall for the cast**. Warm stage times were segment 3.3–3.5 s per user and head ~20 s. Bodies took 18–33 s warm, plus the ~106 s Hunyuan load.
- Gemini image calls: **4** this task (Iraj, Stefanny, Maya, Dev). Lance's face crop is byte-identical to an earlier one, so it hit the new
  cross-user stylize cache (`data/cache/stylize/<face_sha256>.png`). The running total is in `data/logs/gemini_image_calls.jsonl` (8 lifetime).
- ElevenLabs: **10** calls (2 lines per user, stock voices, text in `workers/gpu/demo/cast_lines.json`), made through `POST /api/voice/lines`.
  The API queued the voice_expr jobs and the bridge produced all 10 expression tracks (97–207 frames each at 30 fps).
  `/api/assets/avatars/<uid>/voice/<line_id>/line_expr.json`. Re-running made 0 new calls (lines are matched by exact text).
- Fixed in this task: Hunyuan's exported glTF material had no `metallicFactor` (the default is 1.0, which renders near black without an env map).
  `headmesh.fix_material` now sets metallic 0 and roughness 0.9, and lifts the de-lit baked texture toward the Gemini image's mean color (gain ≤1.35).
  This was applied to all existing heads with `headmesh.py --fix-only`.
- Known cosmetic issue: Iraj's Gemini image has a black band at the top, a Gemini artifact. His GLB is unaffected.
- Contact sheet: `data/cv004/contact_sheet.png` (photo crop | LAM talking head | Gemini stylized | head.glb | on the village body).

Rebake with real selfies (with consent): put `<name>.jpg` in a folder, then
```bash
bash ops/run_gpu.sh start
python -m uv run --with httpx --with "psycopg[binary]" --with python-dotenv workers/gpu/scripts/bake_cast.py --photos <dir> [--users maya,dev] [--lines workers/gpu/demo/cast_lines.json]
bash ops/run_gpu.sh stop
```
It's idempotent: the same photo means no GPU work, and only missing stages are enqueued. It prints a summary table and writes `data/logs/bake_cast_last.json`.
