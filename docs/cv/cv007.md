# CV-007: Face match "unique login" (worker side). Shapes for the API agent.

**Model:** OpenCV Zoo **SFace** (`face_recognition_sface_2021dec.onnx`, MobileFaceNet trained with the SFace loss; 128-d; cosine similarity),
license **Apache-2.0**, sha256 `0ba9fbfa01b5270c96627c4ef784da859931e02f04419c829e83484087c34e79`.
**Detector:** OpenCV Zoo **YuNet** (`face_detection_yunet_2023mar.onnx`), license **MIT**, sha256 `8f2383e4dd3cfbb4553ea8718107fc0423210dc964f9f4280604804ed2552fa4`.
Both run on the **CPU** through OpenCV 4.10 inside the worker gateway process, so they use no VRAM and never compete with SAM 3, LAM or Hunyuan on the GPU.
Disclosure: the weights are Apache-2.0, but like most face recognizers SFace was trained on public face-recognition research datasets,
whose own terms we have not audited. This is fine for a hackathon demo; review it before any production use.
Setup: `workers/gpu/scripts/setup_face.sh` installs `opencv-python-headless==4.10.0.84` into vcv-sam3 and puts the models in `~/village-cv/checkpoints/face/`.

**Not liveness-checked, and not a security control.** A printed photo or a screen showing the person's face will pass. Treat a match as a
fun "is it you?" second factor on top of Auth0, never as the only factor. Liveness and anti-spoofing are out of scope.

## Endpoints (worker :8100, synchronous)
### `POST /face/enroll`  JSON `{ "user_id": "<uuid>" }`
Reads `data/assets/avatars/<uid>/face_512.png` (written by the segment stage) and writes `face_embedding.npy` (128 float32, L2-normalized)
and `face_embedding.json` next to it.
```jsonc
200 { "enrolled": true, "model": "opencv_zoo/sface_2021dec+yunet_2023mar", "dim": 128, "source": "face_512.png",
      "source_mtime": 1791615295.45, "enrolled_at": 1791648859.25, "face_found": true, "faces": 1, "det_score": 0.933,
      "face_box": [x, y, w, h], "timing_s": 0.097 }
404 { "detail": "no face_512.png for this user (upload a photo first)" }
422 { "detail": "no face found in the avatar photo" }
```
### `POST /face/verify`  multipart `user_id`, `file` (selfie jpg/png/webp), optional `threshold`
```jsonc
200 { "match": true, "score": 0.972, "threshold": 0.4, "face_found": true, "faces_in_selfie": 1,
      "enrolled_now": false, "model": "opencv_zoo/sface_2021dec+yunet_2023mar", "timing_s": 0.076 }
200 { "match": false, "score": null, "threshold": 0.4, "face_found": false, ... }     // no face in the selfie
404 / 422 as for enroll
```
- If there's no embedding yet, or `face_512.png` changed since enrollment (new photo / rebake), verify **re-enrolls automatically**
  (`enrolled_now: true`). Calling enroll explicitly is optional.
- The largest face in the selfie is used. `score` is cosine similarity in [-1, 1].
- Suggested API wiring: `POST /api/auth/face-verify` (authenticated, multipart) proxies to the worker with the caller's user_id and returns only
  `{match, face_found}`. Don't persist selfies; the worker deletes its temp copy right after scoring. The API should rate-limit (e.g. 5 per minute).

## Threshold calibration (CC0 cast, `scripts/calibrate_face.py`, results in `data/cv007/calibration.json`)
The sample is tiny and the positives are **not** independent photos. We only have one photo per person, so the positives are LAM-rendered novel
poses and expressions of that person, plus selfie-like degradations of the original upload (re-crop, 0.25× downscale, 0.55× brightness, blur, JPEG q25, mirror).
Negatives are every cast anchor against every image of every other identity, including 4 unused CC0 candidate faces and 2 other people from the crowd photo.

| | n | min | p10 | mean | max |
|---|---|---|---|---|---|
| same person | 50 | **0.502** | 0.560 | 0.799 | |
| different person | 235 | | | 0.119 | **0.291** (p99 0.273) |

| threshold | FAR | FRR |
|---|---|---|
| 0.25 | 9/235 (3.8%) | 0/50 |
| 0.30 | 0/235 | 0/50 |
| 0.363 (SFace's published LFW threshold) | 0/235 | 0/50 |
| **0.40 (chosen)** | **0/235** | **0/50** |
| 0.50 | 0/235 | 0/50 |
| 0.55 | 0/235 | 5/50 (10%) |

**Threshold: 0.40**, roughly the middle of the observed gap (0.291 to 0.502). It can be overridden with env `FACE_MATCH_THRESHOLD` or the per-call `threshold` field.
The lowest positives are LAM renders of Stefanny (0.50–0.53). Real selfies taken on another day, with different light, glasses or beard, will score lower than
these positives, so expect a meaningful false-reject rate in practice. The UI should offer a retry plus the other unique-login options (voice phrase, invite link).
One impostor photo (cc0_c6, a backlit side profile) had no detectable face at all.
