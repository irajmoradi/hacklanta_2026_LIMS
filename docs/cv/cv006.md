# CV-006: Photo → wearable / 3D decoration. Shapes for the API agent.

Both flows use the existing `avatar_jobs` table with `stage='segment'` and an `input.kind` discriminator. The CHECK constraint is unchanged.
The bridge never writes an avatar manifest for these jobs, including on failure. Outputs live under `data/assets/items/<user_id>/<job_id>/`.

**Needed API asset rule:** `items/<uid>/<job_id>/...` should be readable by the owner and their village peers, the same as `avatars/<uid>/...`
(`require_peer`). Today `/api/assets` only serves those keys if a manifest references them exactly.

## 1. `outfit_from_photo`
Input (row `user_id` = the requesting user; the photo is already stored by the API, e.g. `uploads/<uid>/<file>.jpg`):
```jsonc
{ "kind": "outfit_from_photo",
  "photo_asset_key": "uploads/<uid>/<file>.jpg",   // REQUIRED (alias "asset_key"), key relative to data/assets
  "slot": "torso",                                  // "torso" (default) | "head"
  "prompt": "jacket",                               // optional SAM 3 noun; ^[A-Za-z][A-Za-z -]{0,39}$
  "user_id": "<uid>", "consent": true }
```
The photo can show a garment alone or a person wearing it. SAM 3 tries `prompt` first, then the slot list
(torso: shirt, jacket, sweater, t-shirt, dress, top; head: hat, cap, beanie, turban, headscarf), and keeps the best instance.
Result (`status='done'`):
```jsonc
{ "kind": "outfit_from_photo", "slot": "torso",
  "tint": { "primary": "#6e2e3f", "secondary": "#e5b9c6" },     // 2-means over garment pixels; primary = larger cluster
  "tint_share": 0.74,                                          // fraction of garment pixels in primary
  "pattern_png_url": "/api/assets/items/<uid>/<job_id>/pattern.png",   // 256x256 seamless (tileable) swatch, sRGB
  "cutout_png_url":  "/api/assets/items/<uid>/<job_id>/cutout.png",    // RGBA garment cutout (UI preview)
  "prompt_used": "shirt", "garment_score": 0.832, "timing_s": {"total": 3.3} }
```
**Web use:** on the outfit material (`shirt` on `villager_base`, or the jacket/hat material of an outfit GLB), either set
`color = tint.primary`, or set `map = pattern` with `RepeatWrapping`, `repeat (3,3)`, `colorSpace = SRGB` and `color = #ffffff`.
`render/head_preview.html?pattern=…` is the reference: Iraj's villager wearing the plaid swatch, in `data/cv006/wear_crowd_plaid.png`.
Errors: `no garment found in the photo`, `slot must be torso or head`, `prompt must be a short noun phrase`, `input asset missing`.

## 2. `object_from_photo`
```jsonc
{ "kind": "object_from_photo",
  "photo_asset_key": "uploads/<uid>/<file>.jpg",   // REQUIRED
  "prompt": "mug",                                  // optional noun (strongly recommended); falls back to object|mug|plant|toy|instrument
  "user_id": "<uid>", "consent": true }
```
The pipeline is: SAM 3 cutout → Gemini `gemini-2.5-flash-image` "upright low-poly cozy prop, white background" (cached by cutout sha + prompt
version, so a re-run costs no call) → Hunyuan3D-2mini-Turbo shape + Paint-Turbo texture → ≤3,000 tris → normalized to fit a **0.6 m cube**, origin at
the base center, +Y up, front +Z.
Result:
```jsonc
{ "kind": "object_from_photo",
  "glb_url":         "/api/assets/items/<uid>/<job_id>/object.glb",      // ~0.5-0.8 MB, 1024 px texture, matte PBR
  "preview_png_url": "/api/assets/items/<uid>/<job_id>/stylized.png",    // Gemini prop image (thumbnail for the shop/inventory)
  "cutout_png_url":  "/api/assets/items/<uid>/<job_id>/cutout.png",      // SAM 3 RGBA cutout of the original photo
  "faces": 3000, "bounds": [[-0.3, 0.0, -0.23], [0.3, 0.39, 0.23]], "size_m": 0.6,
  "prompt_used": "mug", "object_score": 0.961, "gemini_cached": false, "timing_s": {...} }
```
**Web use:** `GLTFLoader` → place at the house decoration anchor. It's already metric and grounded, so apply no scale.
Errors: `no object found in the photo`, `prompt must be a short noun phrase`, `object_from_photo failed on the GPU worker`.

## Worker endpoints (internal, :8100)
`POST /item/outfit` and `POST /item/object`: multipart `owner`, `item_job_id`, `file`, `slot?`, `prompt?` (or JSON with `image_path` under
the data dir), plus `?wait=true`. Outputs go to `assets/items/<owner>/<item_job_id>/`.

- Peak VRAM: SAM 3 ~5.5 GB, Hunyuan shape 4.4 GB, paint 4.4 GB, never at the same time. An object job evicts SAM 3 to load Hunyuan (load 48–208 s cold),
  so the first object after a SAM 3 job is slow. For the demo, run the objects back to back.
- Prompt v1 (three-quarter view) gave a flat, tilted guitar and a pot-less plant, because SAM 3 "plant" on a top-down photo takes only the leaves. Prompt v2
  (upright, straight front view, add a stand or pot) plus the noun "potted plant" fixed both. That cost 2 of the Gemini calls.
- Gemini image calls used: **5** (mug, plant v1, guitar v1, plant v2, guitar v2) out of the ≤6 budget. Outfits never call Gemini.
  The swatch-stylizing step (optional in the task) was skipped to stay in budget; the raw fabric swatch already reads well.
- Known: Gemini restyles printed graphics (the mug's skull became a heart). Outfit swatches can include a logo edge.
