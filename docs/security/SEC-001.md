# SEC-001 — public API cost and debug audit

Scope: `apps/api/**` and this report. No live-village mutations, provider calls,
deployments, secret copies, or contract changes were made. Tests use synthetic
providers and the remote runner's isolated PostgreSQL test schema.

## Recommended defaults and configuration

All windows reset at UTC midnight. Limits are **per API process**, using a
thread-safe atomic reservation. Failed physical attempts remain charged even if
their database transaction rolls back. Rejected reservations create no counters.

| Resource | Global/day | IP/day | Seat/day |
| --- | ---: | ---: | ---: |
| `LLM` (Gemini + OpenRouter combined) | 300 | 60 | 40 |
| `ELEVENLABS` (TTS + cloning combined) | 60 | 15 | 10 |
| `GPU` (reserved stage/clip units) | 40 | 10 | 8 |
| `PHOTON` (send units, including attachments/retries/replies) | 30 | 30 | 10 |
| `PHOTON_QUEUE` (user-triggered outgoing message admissions) | 30 | 10 | 6 |

Use `COST_<RESOURCE>_<GLOBAL|IP|SEAT>_DAILY`, for example
`COST_ELEVENLABS_GLOBAL_DAILY=60`. Zero denies new work for that dimension.
Negative values clamp to zero; malformed integer configuration fails startup.
The existing `LLM_MAX_CALLS_PER_HOUR` database limit remains in force as well.
Environment loading still uses `VILLAGE_ENV_FILE` at runtime; this task needs no
real provider credentials. Defaults are appropriate for a single-process demo.

429 responses use a string `detail` suitable for existing error toasts and a
`Retry-After` header. Cache reads continue to work at exhaustion. Background
vision admission has an early non-consuming preflight, then an atomic physical
call reservation: concurrent requests can exhaust the budget after preflight;
in that case review falls back safely without spending, after the HTTP response.
GPU background reservations occur before sending the response.

## Proxy and debug policy

Previously debug routes checked only demo auth and `DEMO_DEBUG`. All `/demo/debug`
routes and guest creation/deletion now also require a socket peer exactly
`127.0.0.1` or `::1`, with **no** `X-Forwarded-For` header (even an empty header is
rejected). Public requests receive 404 before database dependencies or effects.
Normal gameplay endpoints remain available; reset/disaster/rehearsal actions stay
behind this gate. Seeding scripts have no public API route.

Only the `127.0.0.1` proxy may supply an IP for quotas. Use the rightmost address
from its appended/overwritten XFF header, ignoring attacker-controlled prefixes.
Other peers cannot override their address. Invalid forwarded addresses share a
single bucket rather than creating unlimited identities. Seats come from resolved
authentication/database identities, never unchecked header strings.

**Deployment requirement:** launch Uvicorn with `--no-proxy-headers` so its outer
middleware does not rewrite the socket peer before the application checks it.
The API Dockerfile now does this. The existing `ops/run_api.sh` launch command
does not specify the flag; the integrator must add it when deploying (that file
is outside SEC-001 allowed paths). Ensure the loopback proxy always appends/overwrites XFF
for public requests; header removal would make public traffic indistinguishable
from direct local traffic. This task did not change the public host/proxy.

## Uploads, assets, CORS, and errors

- Added a 65 MiB whole-request limit, checked both against Content-Length and
  actual streamed bytes before multipart can spool unlimited data. Existing
  image acceptance allows up to 64 MiB, resizing output to at most 10 MiB and
  4096px. Pillow verifies JPEG/PNG/WebP and rejects decompression bombs.
- Voice samples already require 1–3 allowed audio MIME types, nonempty data,
  and at most 10 MiB each. Face selfies have an 8 MiB bounded in-memory parser;
  inbound evidence is limited to 10 MiB. Audio MIME and selfie MIME do not prove
  decodability; the downstream service validates actual audio/face content.
- Asset resolution already rejects absolute paths, dot segments, backslashes,
  drive/stream colons, and resolved symlink escapes. Private upload and consent
  checks remain intact. Asset responses set `nosniff`.
- CORS remains restricted to `http://localhost:5173`; public hosting is same
  origin. No wildcard, reflected origins, or service-key CORS exposure was added.
- Worker photo-item errors previously passed through verbatim. They now use a
  generic message, matching existing avatar/group-photo error handling.
- Validation responses no longer echo invalid input, which could include tokens,
  phone numbers, or upload bytes. Provider failures already use sanitized errors;
  normal FastAPI production 500 responses do not include stack traces.

## Remaining boundaries / follow-up outside allowed paths

- Restarting the process resets counters; multiple API processes have independent
  budgets. Run one process for this demo. Durable/distributed budgets would need
  integrator-owned storage changes; none proposed for this in-process task.
- GPU workers own image-generation caching, automatic stage retries, and bridge
  processing. The API caps new workload admission, including chained stage units;
  it cannot count physical retries or worker Gemini cache misses without a worker
  protocol change. Worker Gemini images are bounded indirectly by GPU admission,
  not included in the 300 API LLM-call counter. Pre-existing queued jobs and direct
  worker/operator access are outside this API limiter. Restrict worker access and
  add worker-side daily physical-call accounting as a separate task.
- Photon delivery authorizations bound API-driven sending; transport-internal
  retries or direct sends in the separate iMessage process need a transport-side
  cap for an exact network-send bound. Outbox leases are charged again on retry.
  The API reserves one text unit, one if audio exists, and one for video or image,
  matching the current transport. Transport-generated validation/error replies
  and reactions bypass the API and remain an iMessage-app follow-up. Queue quotas
  use the sender seat; delivery quotas use the recipient/resolved inbound seat.
- Demo seats intentionally remain impersonable. This change prevents unlimited
  generation and public debug tools; it does not convert judge seats into private
  accounts or stop ordinary permitted gameplay actions by someone choosing a seat.
- Privacy deletions remain usable when generation budgets are exhausted.
  A `STOP` opt-out also commits even if no Photon reply allowance remains.
- Per-IP quotas can be shared by judges behind one NAT/proxy chain. Tune IP caps
  with global caps unchanged if the deployment collapses all judges to one address.
