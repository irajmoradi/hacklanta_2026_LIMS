# API-009 — Smarter Mayor: long-term memory, scaled event table, daily Village Gazette

AI/ML is the main track — deepen the agent. Read AGENTS.md, apps/api/API-00{2,3,4,7}-REPORT.md, Hackathon.pdf
(LLM God/Mayor: weekly recap, prayers, random events "scaled for rewards/downsides", penalties recoverable, Mayor memory
"across weeks"). Another agent (ARCH-001) is adding `app/catalog_registry.py` + migration 008 — don't touch those;
use migration number 009 (additive, idempotent, no BOM). Live API :8010 runs from main; test on a temp port.

1. **Memory**: `mayor_memory` (per village: rolling weekly summaries + notable facts per villager, e.g. "Lance repeats gym
   screenshots", "Stefanny won twice"), written after each weekly finalize/recap and when prayers/events resolve;
   compact (≤ 1.5k tokens) and fed into every Mayor prompt. Endpoint to read it (members) for the "AI at work" panel.
2. **Scaled event table** (`events_table.py`): a vetted table of event templates with difficulty tiers (solo/pair/group,
   effort hours) → reward XP ranges and recoverable penalties (fog, crater, house_downgrade flag, sad pet). The LLM picks
   template + fills specifics; server validates against the table (no freeform rewards). Prayers map to templates.
3. **Village Gazette**: once per day per village (scheduler, budgeted) the Mayor writes a short newspaper (headline,
   3–5 stories about real check-ins/competitions/unlocks, one "gossip" roast respecting roast_ok, weather report).
   `GET /villages/{vid}/gazette/latest` + `/gazette?limit`. Labeled AI-generated with model provenance.
4. Tests (mock LLM): memory compaction bounds, template validation rejects out-of-table rewards, gazette rate limit +
   roast_ok respect, membership checks. Route list in packages/contracts/proposals/API-009.md. Final report per AGENTS.md.
