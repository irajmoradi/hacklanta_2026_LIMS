# SEC-001 — Harden the public deploy against cost abuse and debug exposure

The app is public at https://207-246-81-187.sslip.io (Caddy → tunnel → vite preview → API :8010). Demo seats are chosen with
the `X-Demo-User` header, so anyone on the internet can act as a seat. That's intended for judges, but it must not be able to
burn money or wreck the village. Audit first, then fix in apps/api:
1. Inventory every endpoint that triggers a paid or GPU call (Gemini/OpenRouter, ElevenLabs TTS/SFX/voice, GPU worker,
   Modal fallback, Photon sends, villager-gram video). Write the table to `docs/security/SEC-001.md`.
2. Add a small in-process limiter (no new infra): per-IP + per-seat + global daily caps on those endpoints, configurable via
   env with safe defaults (e.g. ElevenLabs ≤ 60 calls/day global, Gemini ≤ 300/day, GPU jobs ≤ 40/day, Photon sends ≤ 30/day).
   Over cap → 429 with a friendly message the existing toast system can show. Cache hits must not count.
   Trust `X-Forwarded-For` only from 127.0.0.1 (the proxy).
3. Debug/world-changing endpoints (🐞 menu, resets, disasters, seeding) must be off unless `DEMO_DEBUG=1` AND the request comes
   from loopback with no `X-Forwarded-For` (i.e. not via the public proxy). Verify current behavior, fix gaps.
4. Check uploads (size/type limits), path traversal on asset keys, CORS, error bodies leaking stack traces or secrets.
Tests: new pytest coverage for limiter + debug gating; run the full API suite via `ops/remote_run.sh` (see AGENTS.md).
Never call paid APIs or touch the live village — mock providers in tests. Final report per AGENTS.md, including the
recommended cap values and anything you found but did not fix.
