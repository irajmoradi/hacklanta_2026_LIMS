# FIX-011 — Survive API restarts gracefully

When the API (uvicorn :8010) restarts, the vite preview proxy (apps/web/vite.config.ts `/api` → :8010) returns 500 for ~20 s and the UI
shows "Request failed (500)". Fix:
1. Proxy: on ECONNREFUSED/ECONNRESET, return **503** with `Retry-After: 2` (configure `proxy.configure` error handler) instead of 500.
2. Client (apps/web/src/api/client.ts): for idempotent GETs, auto-retry 502/503/504 and network errors with backoff (0.5, 1, 2, 4 s; max ~10 s)
   and show a subtle "Reconnecting…" pill instead of an error toast. Mutations (POST/PATCH/DELETE) retry ONLY if they carry an
   idempotency key; otherwise show a friendly "Village is restarting, try again in a moment" message.
3. Presence heartbeats/polling back off silently during an outage.
4. ops/run_api.sh: start the new server before stopping the old one if feasible (e.g., accept a PORT override), or at least document a
   `restart_api` helper that waits for /health before switching. Keep it simple.
Tests: unit (retry policy), e2e (stop API → page shows Reconnecting → API back → data loads without a reload). Final report.
