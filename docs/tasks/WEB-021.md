# WEB-021 — Explain why you can't buy something; house nameplates only on hover

1. **Shop requirements (R-29).** Stefanny had enough XP for `pet_dog` but couldn't buy it. Root cause: pets need the
   `house_backyard` item (catalog `requires`) AND the `pet_shelter` building unlocked (`requires_building`); the shop doesn't
   say so. For every shop item compute its state from API data (`/shop` gives requires/requires_item/requires_building,
   inventory, unlocks, balance): `owned` · `buyable` · `locked` with a reason list: "Needs Backyard (100 XP) first" (with
   a one-click "Buy Backyard" / jump to it), "Unlocks when the village builds the Pet Shelter", "Need 40 more XP",
   "Earn-only: …" if a `source` field exists. Show it as a clear chip on the card plus a tooltip, disable Buy with the reason
   text, and surface the API's 409 detail text in the toast if a buy still fails. Do the same in the wardrobe/showcase if
   they have buy buttons.
2. **Nameplates on hover only (R-30).** WEB-016's house nameplates ("Stefanny's" + pfp over each door) clutter the town.
   Hide them by default; show on hover of the house (or its nameplate area), on keyboard focus, and for the selected
   villager's house; on touch, show on tap. Keep "click house → profile". Villager name tags stay as they are.
Tests: unit for item state/reasons (pet_dog without backyard → reason), e2e (mock: locked chip + reason; nameplate hidden
until hover). Real-mode screenshot of the shop. Final report per AGENTS.md.
3. **Buy from profile (R-31, Lance).** In the profile Outfit section (WEB-016) and anywhere equipped cosmetics/decorations are
   listed, clicking an item that exists in the shop opens the shop focused on that item with Buy (respecting the lock
   reasons above); "Owned" if you already have it; earn-only/event items show how to get them.
4. **Overlap bug (R-33, Iraj screenshot 13:35).** The bottom dock (Village / Check in / Weekly review / Compete / Shop / Mayor /
   Gazette / My goal) overlaps the "Your little corner" self-card in the bottom-left; WEB-015's "Say cheese · Optional face
   check · Skip" row made the card taller and it now collides with the dock. Fix the layout so no HUD panels ever overlap at
   1280–2560px widths and on laptop heights (~720–900px): reserve the dock's height (CSS var) and stack the self-card above it
   (or dock to the right of the card), make the face-check invite a compact single line or move it into the card's menu, and
   keep the "Drag to explore · Scroll to zoom / reset" hint clear of both. Add a Playwright overlap check
   (bounding boxes of .self-card, dock, hints don't intersect) at 3 viewport sizes.
