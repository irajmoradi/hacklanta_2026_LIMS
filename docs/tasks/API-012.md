# API-012 — Make the Gazette read like a real village newspaper

The live Gazette now uses DeepSeek for the headline, but its stories are templated facts ("11 check-ins recorded today
(UTC).", "Village unlocks: festival_lights, …") and the gossip line is generic. Read apps/api/app/newspaper.py,
memory.py, packages/contracts/proposals/API-009.md + API-011.md. Keep the response shape unchanged (the web adapter
in apps/web/src/api/gazette.ts maps `content.{headline, body, weather, stories[{text, source, user_id?}], gossip{text,
target_user_id}}`).
- Feed the LLM real context: today's check-ins with names + text, evidence verdicts, goals progress, competitions,
  unlocks, crown holder, active events/packs, Mayor memory facts, bribes, external activity signals if any.
- Ask for 3–5 short, specific, funny-but-kind stories that name villagers (set `user_id` on each story), a `body` lede,
  and one gossip item that respects roast_ok (target only roast_ok users; otherwise playful about the town). Human-readable
  weather ("Foggy — the movie-night crater is still smoking").
- Strict validation + one repair retry; fallback stays for real failures. Tests with mocked LLM; full suite green.
- One real generation for the demo village at the end (≤2 LLM calls) via the same code path the scheduler uses; report it.
