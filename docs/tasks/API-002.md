# API-002 — AI agents: provider switch, evidence auditor, autonomous Mayor scheduler, contract v2

Read AGENTS.md, packages/contracts/api.md (see "v2 additions"), packages/contracts/schema.sql (v2 tables are
already applied to the live DB), apps/api/API-001-REPORT.md. Main track is **AI/ML**: the agent loop is the pitch.

1. **LLM adapter**: `LLM_PROVIDER=openrouter|gemini`. OpenRouter: POST https://openrouter.ai/api/v1/chat/completions,
   model `OPENROUTER_MODEL` (deepseek/deepseek-v4-flash), `response_format: json_object`, `"reasoning": {"enabled": false}`
   (otherwise content comes back empty). Same JSON validation path for both. On provider error fall back to the other,
   then to canned output. Record the model used in provenance.
2. **Evidence auditor** (`app/auditor.py`): when a check-in has `evidence_asset_id`, run a background review with
   Gemini vision (`gemini-2.5-flash`, Vertex express key) given image + goal + check-in text. Output schema
   {verdict, confidence, reason}. Store in `evidence_reviews`; activity_event `evidence_reviewed`; expose in CheckIn
   and the review route. suspicious/rejected withholds the progress XP bonus until a village owner overrides
   (add `POST .../check-ins/{cid}/review/override`). Never block the request on the model call.
3. **Mayor scheduler** (`app/scheduler.py`, started in app lifespan, `MAYOR_SCHEDULER=1` enables it, on by default in
   dev with `MAYOR_TICK_SECONDS=300`): each tick, per village, the LLM looks at recent activity and *decides* whether
   to act — nudge an idle villager (written as the most active friend, respecting roast_ok / agent_msgs_ok), announce a
   random event/challenge (validated bounds), or do nothing — always with a stated reason.
   Rate limits: max 3 agent messages per user per day, max 1 new event per village per 6h. Messages for users with
   phone_e164 go to `mayor_outbox` (optional ElevenLabs voice note only if `MAYOR_VOICE=1`); every decision goes to
   the agent log (`GET /villages/{vid}/agent-log`).
4. Implement the rest of v2: check_in_keys idempotency, evidence on check-in, goal status, event completion,
   outbox claim/sent/failed on `mayor_outbox`, `/internal/assets/{key}`, inbound mapping by phone (earliest village).
5. Docs: default port is 8010 (`ops/run_api.sh` runs it — do not edit that file).

Tests (pytest, `village_test` DB, all external calls mocked): provider fallback + empty-content handling, auditor
verdict storage + XP withholding + override, scheduler rate limits and roast_ok, outbox claim idempotency, event
completion awards once. One real smoke each: an OpenRouter JSON call and Gemini vision on a generated test image.
Commit on your branch; final report per AGENTS.md.
