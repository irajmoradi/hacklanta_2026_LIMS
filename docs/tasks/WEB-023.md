# WEB-023 — Instant portraits + drag-to-rotate previews

1. **Portraits (R-39).** Each LAM `avatar.zip` is ~4 MB; the app downloads all of them over the public tunnel on load, with no
   HTTP caching. Fix:
   - Name tags, lists, feed and inbox use only the small `face_512.png` (or a ~96px thumbnail you generate on the API side,
     cached on disk) and never fetch the zip.
   - The Gaussian head loads lazily, only when a profile or showcase is open and visible (IntersectionObserver), one at a time,
     showing the static portrait plus a subtle shimmer until it's ready.
   - API asset responses get `Cache-Control: public, max-age=31536000, immutable` for content-addressed/revisioned files
     (append `?rev=<manifest rev>` in URLs) plus ETag/If-None-Match → 304, and gzip only for non-zip types.
   - Optionally prefetch the current seat's own zip during idle time.
   Measure before/after (bytes transferred on first load and second load in the real-mode e2e) and put the numbers in the report.
2. **Drag to rotate (R-40).** In the Wardrobe and outfit/showcase 3D previews, the auto-spin pauses on pointer-down. Drag rotates
   the villager (yaw, plus a small clamped pitch) with inertia, scroll or pinch zooms within limits, and double-click resets.
   Auto-spin resumes after 4 s idle. Touch works.
Tests: API (cache headers/304), web unit (lazy-load gating), e2e (no zip requests on town load; drag changes rotation).
