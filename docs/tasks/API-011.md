# API-011 — Photo items (CV-006) as rewards, event packs, and a real (non-fallback) Gazette

Read docs/cv/cv006.md (exact job input/result shapes; example jobs left for Iraj: outfit 8a3352f1-…, object 368e3e4d-…),
docs/tasks/ARCH-003.md (event_packs registry section — may or may not be merged yet; handle both), API-009/010 proposals.
ARCH-003 runs in parallel on catalog_registry.py/packages/catalog — don't edit those. Migration 011, additive, no BOM.

1. **Photo items**: `POST /villages/{vid}/items/from-photo` multipart (`kind: outfit|object`, `slot` for outfits, optional
   `prompt`, consent) → enqueue the CV-006 job (stage `segment`, `input.kind`) → `GET .../items/jobs/{id}`; on success create
   a **custom inventory item** owned by the user (`custom_items`: id, owner, kind, slot, tint/pattern_url or glb_url, preview,
   source_job) — equippable like catalog items (torso/head slot tint+pattern; object → house decoration placed in their yard).
   Gate behind a reward: owning a `photo_item_token` (granted by weekly crown, event reward, or purchasable for XP via the
   registry if present); consume one token per creation. Add the `items/<uid>/…` asset rule (owner + village peers).
2. **Event packs**: when the Mayor's chosen event template has a `pack` (or the registry `event_packs` exist), set the village's
   active cosmetic pack + weather for the event window; expose `world.active_pack` in the village payload.
3. **Gazette quality**: the live publish path produced `fallback:gazette-v1` (canned) on the integrator's manual run — find why
   (provider error? schema mismatch with DeepSeek? missing context?) and fix so OpenRouter/Gemini produce a real issue; keep the
   fallback for real failures. Prove with one real generation (≤2 LLM calls) and record the model in provenance.
Tests (mock worker/LLM) for all; full suite green. Final report per AGENTS.md.
