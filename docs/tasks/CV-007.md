# CV-007 — "Unique login": face match against your villager's photo (worker side)

Hackathon.pdf: "Auth0 for authentication, with a unique log in process … face match against your avatar photo, voice
phrase, invite links". Build the CV piece as a worker stage; the API/web wiring is a later task.
- Pick a permissively licensed face-embedding model that runs on sm_120 (e.g. an ArcFace/InsightFace-style model whose
  weights are licensed for this use — check and record the license; if the obvious ones are non-commercial-only, a
  research-only demo is acceptable for the hackathon but must be disclosed; or use a SAM 3 face crop + a CLIP/DINO
  embedding as a fallback). Liveness is out of scope — say so.
- Worker: `POST /face/enroll {user_id}` computes the embedding from that user's existing `avatars/<uid>/face_512.png`
  and stores it (file under data/assets/avatars/<uid>/face_embedding.npy); `POST /face/verify` multipart selfie +
  `user_id` → `{match: bool, score, threshold, face_found}`. Calibrate a threshold on the CC0 cast (same-person vs
  different-person pairs from data/inputs/*) and report the ROC-ish numbers honestly (tiny sample).
- Bridge/job not required (synchronous ≤1 s warm is fine); document shapes in docs/cv/cv007.md for the API agent.
- Keep VRAM small; never co-resident with Hunyuan. Restart live services after changes and leave them running.
Small commits, no push, don't edit apps/. Final concise report with license, threshold, timings.
