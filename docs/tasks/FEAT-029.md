# FEAT-029 — Real sign-in for the team + judges: Auth0 login, seat claiming, two-laptop demo (R-179, owner)

Owner (Iraj): "Do the Auth0: give credentials to all of us, but create a thing for judging so we can show judges we can easily
log in as two different people on two separate laptops and have a persistent, synced world."
Auth0 is already wired (D-006/D-014/D-043: SPA "Village Web" + API "Village API"; `apps/web/src/Auth.tsx`;
`apps/api/app/auth.py` validates RS256 tokens; prod currently runs `VITE_DEMO_AUTH=1` "Play as"). Policy: **no passwords
are ever generated by us or posted anywhere**; people sign in with their own Auth0 account (Universal Login sign-up with
email/password, or a social connection if the tenant has one enabled).
1. **Seat claiming:** after Auth0 login, an unlinked account sees "Claim your villager": enter a **single-use claim code**
   to link this Auth0 `sub` to an existing seat (Iraj, Lance, Stefanny, Mario). Judges never sign in themselves; the team
   demos it. Codes: random, single-use, hashed at rest, expire in 72 h, created by an
   operator CLI (`python -m scripts.claim_codes --village <uuid> --seat <uuid>`), printed once to the operator's terminal.
   A linked account always lands in its own seat. Unlinked accounts with no code go to normal onboarding (create/join).
   Migration: next free number, idempotent, folded into schema.sql.
2. **Login UX, both live at once:** the current no-login "Play as" experience stays exactly as it is and stays the default
   (owner: "keep the one without login live"). Add a clear "Sign in" option alongside it (top bar / landing) for real
   accounts; signed-in users use their token, everyone else keeps using Play as. Sign out in Settings. Tokens in memory /
   refresh per the Auth0 SDK, never in localStorage by our own code. Demo auth and Auth0 must work at the same time on prod.
3. **Judge demo (we drive, judges watch):** `docs/auth/JUDGE_LOGIN.md`: two teammates' laptops, each signed in with their
   own Auth0 account (e.g. Iraj and Mario), walk toward each other and see each other move in real time, decorate the Hall in one and see it update in the other,
   reload and see everything persisted. Make sure the overworld/realtime and house interiors key off the authenticated user
   exactly like demo seats do (per-connection keys, FEAT-023).
4. **Prod config (don't deploy it yourself):** in the report, list the exact env changes to enable Sign in on prod alongside
   demo auth (Auth0 vars, callback/logout URLs for https://thefriendshipvillage.vodka) and how to turn Sign in off again.
Tests: API (token → user mapping, claim code single-use/expiry/wrong village/already-linked, demo header still works when
enabled and is rejected when disabled), web unit tests, Playwright with a mocked Auth0 (no real tenant calls) at 1440/390
via `ops/remote_run.sh`. Final report per AGENTS.md.
