# API-013 — "Unique login": face check as a second, playful step after Auth0/demo login

Read docs/cv/cv007.md (worker `/face/enroll`, `/face/verify` shapes; threshold 0.40; no liveness — a photo of a
photo passes) and the integration notes at its end. Additive migration 013 if you need a table (no BOM).
- `POST /api/auth/face-verify` (authenticated; multipart `file`): proxies to the GPU worker (`GPU_WORKER_URL`) with the
  **caller's own** user_id only; returns `{match, face_found}` (no raw score to the client); never stores the selfie;
  rate limit 5/min per user; 503 with a friendly message when the worker is down.
- On match, set a short-lived "face verified" flag for the session/user (e.g. `face_verified_at`) and award a one-time
  "Recognized by the village" badge via the XP ledger (idempotent). Expose `face_verified_at` in `/me`.
- `POST /api/auth/face-enroll` (self only) to refresh enrollment after a new avatar photo.
- Tests with a mocked worker (match, no match, no face, worker down, rate limit, can't verify someone else).
Route list in packages/contracts/proposals/API-013.md. Final report per AGENTS.md.
