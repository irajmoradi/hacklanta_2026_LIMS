# CV-003 — Stylized villager from the photo (Mercedes "Best CV" story) + supervised GPU services

The village currently uses a preset rigged chibi (`apps/web/public/models/villager_base.glb`, from ASSET-001: head bone
`Head`, materials skin/hair/shirt/pants/shoes, clips idle/walk/wave/cheer) tinted with SAM 3 traits.json colors.
Goal: make each villager visibly *that person* in the village, using the CV spec's zero-rigging-risk path
("generated head on a preset body"), bounded attempts, honest fallbacks.

1. **Stylize** (Gemini image editing via Vertex express key — check the current image-capable model available to
   that key, e.g. gemini-2.5-flash-image; ≤10 calls total): face_512/full_body + traits → a chibi low-poly head
   image, fixed prompt for a consistent style. Save `stylized_head.png`.
2. **Head mesh**: TRELLIS.2 (or TRELLIS / Hunyuan3D-2 if TRELLIS.2 won't build on sm_120 within 2 repair attempts)
   on stylized_head.png → GLB, decimate ≤5k tris, normalize to the preset body's head scale/origin. Save
   `avatars/<uid>/body/head.glb`. If no 3D generator works in time: produce a flat-shaded textured "card" head from
   the stylized image (billboard-ready PNG) and say so.
3. **Worker + bridge**: new stage `body` (`POST /avatar/body`), bridge chains segment → head(LAM) → body; manifest gets
   `body: {kind:"preset", preset_id:"villager_base", colors, head_glb_url?}` (additive field — note it as a
   proposed contract change).
4. **ops/run_gpu.sh**: one command that starts the WSL worker + the Windows bridge loop, with logs in data/logs and
   a stop script; restart-safe.
5. Run it on the 3 CC0 samples; save a contact sheet of stylized heads + rendered GLB heads to data/cv003/.
Measure time/VRAM per stage. Never more than one heavy model on the GPU. Commit on cv/CV-003; final report.
