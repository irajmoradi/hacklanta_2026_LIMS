# CV-006 — Photo → wearable or 3D decoration (the "make it real" reward)

Hackathon.pdf: "Reward could also be ability to give someone else or themselves a new outfit — use computer vision".
Two worker stages, reusing what's installed (SAM 3, Gemini image via Vertex key, Hunyuan3D-2mini). New avatar_jobs stage
names would violate the existing CHECK constraint (`segment|head|body|voice_expr`) — so use stage `segment` with an
`input.kind` discriminator (`"outfit_from_photo"` | `"object_from_photo"`), like the group-photo path did. Document input
/result shapes in docs/cv/cv006.md for the API agent that will add routes later.

1. **outfit_from_photo**: photo of a garment (or a person wearing it) + target `slot` (torso|head) → SAM 3 text prompt
   ("shirt", "jacket", "hat"…) → dominant colors + a small seamless pattern swatch (crop + tile, 256×256) → output
   `{tint: {primary, secondary}, pattern_png_url}` the web can apply to the existing outfit GLB materials
   (`shirt`/`jacket`/hat materials). Optional: Gemini image edit to stylize the swatch to the village's low-poly palette.
2. **object_from_photo**: photo of an object (mug, plant, guitar, plushie) → SAM 3 ("object" or a user-provided noun) cutout →
   Gemini stylize to "low-poly cozy game prop, white background" → Hunyuan3D-2mini → GLB ≤3k tris, normalized to fit a
   0.6 m cube, origin at base → `{glb_url, preview_png_url}` placed later as a house decoration.
Outputs under `data/assets/items/<user_id>/<job_id>/…`. Budget: ≤6 Gemini image calls total (cache by input hash), one heavy
model on the GPU at a time. Test with CC0 photos (record sources). Restart the live services after changes and leave them
running. Contact sheet → data/cv006/. Commit on cv/CV-006; final concise report with the exact shapes and timings.
