# API-010 integration proposal and task report

All routes below have `/api` prefix and use existing bearer/demo authentication.
Apply `apps/api/migrations/010_social.sql` before routing traffic to this build.
The migration is additive, replayable, and UTF-8 without BOM. No shared schema edits.

## Routes

| Method | Path | Request / response |
| --- | --- | --- |
| POST | `/villages/{vid}/messages` | `{to_user_id: UUID, text: string, kind?: "message" \| "poke" \| "cheer"}`; 201 message row |
| GET | `/villages/{vid}/messages` | `box=inbox\|outbox` (default inbox), `limit=1..200` (default 50), `offset>=0`; `{messages: Message[], unread_count: integer}` |
| GET | `/villages/{vid}/messages/unread` | `{unread_count: integer}` for the current recipient and village |
| POST | `/villages/{vid}/messages/{message_id}/read` | No body; message row, original read timestamp preserved on retry |
| POST | `/villages/{vid}/mayor/bribe` | `{xp: integer, wish: string, currency?: "xp" \| "sol_intent"}`; 201 `{bribe, balance, receipt}` |
| POST | `/villages/{vid}/presence/heartbeat` | `{x: number, z: number, activity?: string}`; `{online: Presence[]}` |
| GET | `/villages/{vid}/presence/stream` | SSE `event: presence`, `data: {"online": [...]}` every second, including immediately |
| DELETE | `/me` | Required `{confirm: "DELETE"}`; `{deleted: true, audit_id: UUID}` |

Message row: `{id,village_id,from_user_id,to_user_id,text,kind,created_at,read_at}`.
UUIDs are strings; dates are ISO timestamps; `read_at` starts null.
Text is trimmed, nonempty, at most 2,000 characters. Extra input fields rejected.
Sender and recipient must belong to the village; self-messages rejected (422).
Listing never exposes third-party conversations. Only the recipient can mark read;
missing/inaccessible messages return 404. Membership failures return 403.
Twenty messages per sender per rolling minute across all villages; concurrent sends
serialize on the user row; excess returns 429 with `Retry-After: 60`.
Poke/cheer feed events include `message_id`, `to_user_id`, and `text`. Ordinary
messages do not enter the feed or Mayor context. User text remains untrusted data.
The existing generic feed renderer renders the event kind; web can render payload text.

Recipient consent plus a configured phone enqueues a `mayor_outbox` row, kind
`villager_message`, text `via Village from <display_name>: <text>`.
Existing service claiming rechecks current opt-in/phone/membership. This endpoint
does not contact Photon or send a message itself. The new FK `villager_message_id`
cascades relay deletion when either party's account/message is deleted.

## Bribes / API-009 handoff

`mayor_bribes` columns: `id,village_id,user_id,currency,xp,wish,status,created_at`.
XP is a strict integer 1..10,000; wish trimmed/nonempty, at most 1,000 characters.
Balance insufficient: 409. Member locking uses the same lock as shop purchases;
bribe insert, negative ledger delta, and XP feed event commit atomically.
Ledger reason is `mayor_bribe`, source key `bribe:<UUID>`.
Each accepted POST creates a distinct purchase; clients must not automatically retry
an ambiguous network result (no client idempotency key in this task's request shape).

`currency:"sol_intent"` requires XP zero (default) and records `status:"intent"`.
No SOL amount, transaction, payment, XP debit or event benefit is claimed.
No provider call is made; receipts are templates.

`await app.bribes.pending_bribes(conn, vid)` is a read-only helper with no model calls
or mutations. It returns pending XP rows oldest first, plus `selection_weight`
(Postgres numeric, `1 + min(xp,1000)/100`) and `reward_bonus_xp` (`min(xp,100)`).
API-009 should treat wishes as untrusted data, use these bounded hints in event
selection/scaling, and set chosen rows `status='consumed'` in the same transaction
as event creation. Existing event reward caps still apply. Intents are excluded.
The scheduler is outside this task's scope and has NOT been changed; event influence
requires API-009 to consume this handoff. No event outcome is guaranteed to members.

## Presence

Presence: `{user_id,x,z,activity}`. Coordinates finite and within +/-10,000;
activity trimmed, 1..80 characters (default `idle`). Each user has one latest
position per village, independent of tab count. Heartbeats expire after 30 seconds
using a monotonic clock. Stream connection itself does not renew presence.
SSE sends bounded-rate snapshots; slow clients do not accumulate a queue.
Each iteration releases its database connection before yielding and revalidates
membership; departure/deletion closes the viewer's stream. Disconnect cancels it.
Use authenticated fetch streaming (native EventSource cannot set bearer headers).
State is per app/process; restart clears it. Multiple workers require sticky routing
or a future shared broker. No persistence, GPU, or generated avatar is required.

## Deletion policy and operational limits

Erases user/memberships, inventory, goals/XP, check-ins/idempotency/reviews, attributed
feed history, avatars/jobs, generated voice lines, mail/bribes and recipient/relay
outbox. Also removes user references in weekly audit tables. Owned or audited
competitions are removed because the existing competition contract cannot retain
a nonfriendly competition without an auditor. Other competitions lose this user's
entries/participation and results containing their UUID. UUID-attributed inbound
cache/feed payloads are removed.

Ownership transfers to the remaining member with oldest `joined_at` (UUID tie break).
An empty village is removed, including its non-FK time-series history. Audit stores
only a fresh random ID and timestamp, no user ID, name, phone, or auth subject.

Deletes canonical `uploads/<uid>`, `avatars/<uid>`, `voice/<uid>` and per-village
`evidence/<vid>/<uid>` directories, including unused uploads. Group photos uploaded
or claimed by this user are removed in full from both source and crop directories;
peers keep their independent copied avatar files. Queued source-copy jobs are removed.
Paths are server-derived and confined to configured asset storage, with junction /
symlink escape checks. No external URLs or manifest paths are recursively deleted.

Calls the existing ElevenLabs deletion adapter; provider failure returns 502/503
before local erasure. Already absent clone (404) is accepted. Relevant running GPU
jobs return 409, requiring completion/operational cancellation and a deletion retry;
queued jobs cannot start while deletion holds the jobs-table lock. Storage failure
returns 503 and rolls back DB removal so the user can retry. Already deleted files
and provider deletion cannot roll back with PostgreSQL. Crash/commit failure can
therefore leave an account whose files/clone need regeneration or a deletion retry.

Scope is the API database and configured shared asset directory. Separate GPU disks,
backups, Auth0 identity, already delivered iMessages, and external provider logs need
their owners' retention/deletion processes. Legacy generated prose and inbound cache
without user attribution cannot be exhaustively mapped to a user by this schema.
API-009 memory/newspaper data will need a user-erasure hook when integrated.

## Teammate trial

Set `VILLAGE_ENV_FILE` to the existing external secret file. For an isolated run:
`python -m uv run --directory apps/api pytest -q tests/test_api010.py`.
Tests create a private schema in `village_test`, mock providers, use synthetic files,
and include a real HTTP/SSE subprocess on an ephemeral port; port 8010 is untouched.

For manual development, migrate an explicitly selected development database with
`python -m uv run --directory apps/api python scripts/migrate.py`. Set `DEMO_AUTH=1`,
`MAYOR_SCHEDULER=0`, and Windows `UVICORN_LOOP=app.runtime:selector_loop`, then start
uvicorn on a free port such as 8020. Use `/docs` with
`X-Demo-User: 13370000-0000-4000-8000-000000000001`. Seed village UUID ends `000000000000`;
peer UUID ends `000000000002`. Use disposable users for deletion tests.
