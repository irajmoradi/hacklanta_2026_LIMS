# API-006 additive contract proposal

Implementation lives in apps/api and apps/imessage; shared api.md/schema.sql and GPU/web code
were not changed. Integrator should adopt the following additions.

1. `POST /api/internal/inbound` still requires `X-Service-Key`. Body adds optional
   `message_id: string` (1..500 characters), supplied by this agent as `imessage:<provider-id>`.
   A durable receipt stores the request hash and response in the same transaction as command
   effects. Identical retries return the saved response; ID reuse with different phone/text is
   409. Legacy callers without IDs remain supported but lack effect deduplication.
   Response: `{reply_text: string, processed_checkin: boolean}`. The latter controls tapbacks.
   Unknown/ambiguous phone or absent membership now yields HTTP 200 with generic invite
   guidance and `processed_checkin=false`, without village data. Auth/validation remain 401/422.
2. Command dispatch: `checkin:`, `progress:`, `goal:`, `status`, `pray:`, case-insensitive `STOP`,
   and free text. Current-week active goal is required for progress; missing/empty/overlong
   command data gets friendly guidance without mutation. STOP sets `users.agent_msgs_ok=false`
   through this internal route and cancels pending/claimed items; it does not disable reactive
   commands. AI text is labeled. Only `pray:` creates an event. Free text uses the sender's
   context and has no event side effects. Oldest membership selects the village.
3. `GET /api/internal/outbox` adds optional integer `limit` (1..100, default 100). Agent uses 1
   so queued items do not wait for earlier sends while their leases expire. Existing leased
   claim, sent/failed acknowledgements and service asset paths are unchanged.
4. `/api/me` village entries add `joined_at` (ISO timestamp), with deterministic ordering by
   membership join timestamp then village ID, replacing village creation order.
5. `portrait.placeholder` is an additive boolean. Initials fixtures set true. Stored manifests
   preserve an explicit value; otherwise the API projects `users.portrait_placeholder` (new,
   non-null boolean, default false). A seeder/operator can mark synthetic stand-in portraits
   through that column; no existing real-person rows are automatically reclassified. Photo
   jobs include `input.portrait_placeholder` so the bridge can copy it into produced manifests.
   Propose that bridge preserve this flag; it is outside this task's allowed paths.
6. `apps/api/migrations/005_imessage.sql` adds the user column and `inbound_messages`
   (`message_id` PK, `request_hash`, nullable JSONB `response`, `created_at`). It is additive,
   idempotent and UTF-8 without BOM. Apply to a deployment before serving this build. The
   response is nullable only during its transaction and committed together with effects.

Future delivery guarantees: existing leases have no fencing token or transport idempotency
key. Add those plus lease renewal and durable per-part delivery receipts before claiming
exactly-once external delivery. STOP cannot retract an already in-flight provider request.
Receipt retention is currently indefinite; define a provider replay horizon before pruning.
