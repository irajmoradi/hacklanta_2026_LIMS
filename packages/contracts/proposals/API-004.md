# API-004: voice onboarding, expression jobs, profile and cost guards

Implementation branch: `api/API-004`. All paths below include `/api` and require user
authentication. Shared schema/api.md are unchanged. Apply
`apps/api/migrations/004_voice_budget.sql` before deploying this build (the API migration
runner applies all additive migrations). This work only migrated the isolated test database.

## Web-facing routes

| Method | Route | Request and response |
| --- | --- | --- |
| GET | `/api/me` | `{user, villages}`. Self-only user now includes `phone_e164`, `voice_id`, `voice_consent`, `voice_consent_at`, `voice_consent_version`. Each village includes `role: "owner"\|"member"` and `is_auditor_this_week: boolean`. |
| PATCH | `/api/me` | Partial JSON `{display_name?, phone_e164?, roast_ok?, agent_msgs_ok?}`; returns the same shape as GET `/me`. |
| POST | `/api/me/voice` | Multipart repeated `files` (1–3 audio memos) and `consent=true`; returns `{voice_id, voice_consent:true, voice_consent_at, voice_consent_version}`. |
| DELETE | `/api/me/voice` | No body; deletes the provider clone and clears all four voice/consent fields. Returns those fields, null except `voice_consent:false`. Repeat deletion succeeds. |
| POST | `/api/voice/lines` | Existing `{user_id,text}`; returns `{id,audio_url,expr_url:null,job_id}`. Queues an expression job even when no head is ready. |
| GET | `/api/voice/lines/{id}` | `{id,audio_url,expr_url,job_id}`. Owner/shared-village access, matching existing voice asset access. Poll until `expr_url` is non-null. |
| POST | `/api/villages/{vid}/mayor/recap?voice=true` | Existing event response plus `{line_id,audio_url,expr_url:null,job_id}`; narration uses the Mayor stock voice. Default false preserves the previous response and makes no TTS call. |
| POST | `/api/villages/{vid}/mayor/nudge` | Existing `{target_user_id}`. Voiced response also includes nullable `line_id`, `expr_url`, `job_id`. `MAYOR_VOICE` retains control of nudge TTS. |
| POST | `/api/avatars/{uid}/photo` | Existing consent/multipart request. Images over 10 MiB or either dimension over 4096 px are resized/re-encoded server-side. |
| POST | `/api/villages/{vid}/evidence` | Same image normalization as avatar photo uploads. |

PATCH accepts a trimmed 1–100-character display name, E.164 phone (`+` followed by
7–15 ASCII digits, first nonzero), and booleans. Omitted fields stay unchanged. Only
phone accepts explicit null to clear it. Unknown fields and invalid/null names or booleans
return 422. Phone and consent metadata are exposed only on the caller's `/me`, not shared
villager profiles. CORS now allows PATCH and DELETE.

Auditor status reflects the already initialized current UTC Monday week, including any
replacement. `/me` never assigns an auditor or calls a provider. Before initialization it
returns false; use the existing `/weekly/current` workflow to initialize.

## Voice consent and provider behavior

Show this text next to the mandatory consent checkbox (version `village-voice-v1`):

> I confirm these recordings are my own voice and consent to ElevenLabs cloning it for
> AI-generated speech in Village, including speech requested by village friends.

The server records its version and acceptance timestamp. Uploads are sent directly to
ElevenLabs as multipart files, without retaining raw voice samples in application storage.
One clone per user: requests serialize under a user-row lock, and an existing voice returns
409. Delete before replacing. Label is `Village — <current display_name>`.

Supported audio MIME types: audio/mpeg, audio/mp3, audio/wav, audio/x-wav, audio/mp4,
audio/x-m4a, audio/aac, audio/ogg, audio/webm, audio/flac. MIME parameters are ignored.
Each memo must be nonempty and at most 10 MiB. Provider validates the audio contents.
Errors: 422 consent/count, 415 MIME, 413 size, 409 existing voice, 503 missing provider
configuration, 502 provider failure. Provider errors never include raw response details.
Failed deletion retains local state; provider 404 is treated as already deleted.

Provider request shapes follow the official [IVC creation documentation](https://elevenlabs.io/docs/api-reference/voices/ivc/create).
No real clone or paid smoke request was performed. External provider creation and the DB
commit cannot be atomic: a provider success followed by process/DB failure can leave an
orphan voice requiring provider-side reconciliation. No automatic paid creation retry occurs.

## Expression playback

Migration adds `voice_lines.job_id` referencing `avatar_jobs`; `expr_key` already exists.
New jobs have stage `voice_expr` and input `{audio_key,line_id,user_id}`. The existing
CV-002 bridge writes `avatar_jobs.result.expr_url`; polling reads it only after status
`done`, without needing bridge changes. Existing `voice_lines.expr_key` remains a fallback.
Queued, running and failed jobs keep `expr_url:null`; audio remains available with the GPU
offline. `job_id` permits the owner to inspect the existing `/jobs/{job_id}` endpoint.

Mayor narration queues only when the target's latest manifest has `portrait.kind=lam_head`:
the nudge target for nudges and the requesting member for recap narration. The recap is
stored as that member's line but synthesized using the stock Mayor voice, never their clone.
Nudge audio retains the selected friend's voice while expressions belong to the target.
The line response supplies `line_id` for polling. Recap narration errors return the normal
voice 502/503 and roll back event creation; narration is opt-in.

## Image and cost policies

Valid JPEG/PNG/WebP uploads needing normalization have EXIF orientation applied, fit within
4096×4096 preserving aspect ratio, and are encoded as JPEG quality 85. Additional downscaling
ensures at most 10 MiB. Normalization is deterministic for deduplication. Small images retain
their existing bytes. A 64 MiB compressed input limit and Pillow decompression-bomb protection
remain; corrupt/unsupported images return 415. Oversized transparent images become RGB JPEG.

Scheduler ignores case-sensitive `QA-*` names and villages without a human check-in or
recognized human mutation in the preceding 48 hours. Recognized events include village
creation/join, goals, purchases, evidence/photo uploads, explicit Mayor events, weekly grading/
finalization/votes, and competition mutations. Agent decisions, automatic Mayor messages,
generated voice lines and GPU completions cannot keep an abandoned village active.
Explicit member requests remain available in QA/inactive villages.

`LLM_MAX_CALLS_PER_HOUR` defaults to 60; zero disables paid model calls. A PostgreSQL table
`llm_hourly_budget` atomically counts physical calls across API processes/villages per clock
hour. OpenRouter repair attempts, fallback requests, Gemini text and Gemini vision all count.
Reservations commit independently, so failures and enclosing transaction rollbacks do not
refund calls. Database failures stop generation. Throttling uses existing conservative
fallbacks and writes `agent_decision` with `agent=budget`, `action=throttled` into the affected
village's `/agent-log`. Provider tooling outside a village still consumes the global budget.
ElevenLabs is not an LLM and is outside this budget; existing explicit-action/nudge voice
guards remain. Old hourly rows are retained (one per used hour).
